# Security Policy

## Supported code

Security fixes are evaluated against the repository's current default branch. Older snapshots, archived branches, local experiments, and third-party services are not separately supported unless the repository states otherwise.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting / Security Advisory flow when it is available for this repository.

If private reporting is not available, open a minimal public issue asking for a private contact channel. **Do not include exploit details, credentials, tokens, personal data, candidate or student records, uploaded documents, private messages, or other sensitive material in a public issue.**

Include only what is necessary to reproduce the affected version and surface after a private channel is established.

## Scope and expectations

- Do not test against real users, accounts, institutions, or third-party systems without authorization.
- Do not perform destructive testing, denial-of-service testing, credential attacks, or data exfiltration.
- Demo credentials, synthetic fixtures, and local-only flows are not security boundaries unless the repository explicitly documents them as such.
- Dependency or platform vulnerabilities should identify the affected package/runtime and a reproducible impact on this repository.
- This project does not promise a bug bounty or monetary reward.

Thank you for reporting security issues responsibly.
