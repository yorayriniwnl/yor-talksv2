# Third-party SDK, service and dependency audit

Audit date: **17 October 2026**. Release status: **BLOCKED / NO-GO**. This is a technical inventory of the current source, lockfile and installed package metadata. It does not approve a processor, international transfer, license interpretation or production account. No provider credentials or personal data are reproduced here. Use [release gates](RELEASE_GATE_STATUS.md), the [launch runbook](PRODUCTION_LAUNCH.md) and [asset register](ASSET_PROVENANCE_REGISTER.md) for the approval records.

## Dependency and supply-chain evidence

`pnpm audit --json` on 17 October reports **0 known vulnerabilities** across **713 dependency instances** (266 production, 429 development, 28 optional). This is registry advisory evidence at that time, not proof of absence of vulnerabilities. CI now runs `pnpm audit` across all scopes: many shipped browser libraries are under `social/package.json`'s `devDependencies`, so the previous `--prod` command omitted them.

The [machine-readable installed license inventory](audits/2026-10-17/dependency-licenses.json) comes from `pnpm --filter '*' licenses list --json`, covering all workspace importers and **652 package records**. The three metadata-unknown entries are `@replit/vite-plugin-cartographer` 0.5.21, `@replit/vite-plugin-dev-banner` 0.1.2 and `thirty-two` 1.0.2. The latter includes an installed `LICENSE.txt` with MIT terms and Chris Umbel's notice; the JSON deliberately retains its unknown metadata rather than inventing a package field. The two Replit development plugins have no license file in their inspected installed package directories. They are conditionally imported only for development with `REPL_ID`; retain an unresolved licensing gate for any distributed build/container that includes them. `lucide-react` reports ISC but its installed license also carries MIT notices for Feather-derived portions; preserve both applicable notices.

No automatic dependency deletion was justified: conditional development imports, generated contract tooling, native packaging and runtime imports were identified. A safe package cleanup needs a release-scope/import graph and lockfile regeneration, rather than assuming every package absent from one screen is unused.

The workflow uses explicit `contents: read`, immutable action SHAs, a Node/pnpm version matching the package metadata, frozen/offline image dependency installation and an explicit `allowBuilds` list in `pnpm-workspace.yaml`. Containers still use mutable release tags; image digests/SBOM/signature and update ownership must be recorded for the actual release. The API image currently installs the whole workspace, including development tooling; package/image size reduction and license notices are separate from a clean advisory result. Historical or current hosted CI status is recorded in [release gates](RELEASE_GATE_STATUS.md), not inferred from local tests.

Push-host references checked for the outbound-request repair: [Chrome FCM example](https://developer.chrome.com/blog/push-notifications-on-the-open-web/), [Mozilla production endpoint](https://mozilla-services.github.io/autopush-rs/), and [Apple Web Push network destinations](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers). Host validation is a technical restriction; actual browser support and provider agreements remain unaccepted.
