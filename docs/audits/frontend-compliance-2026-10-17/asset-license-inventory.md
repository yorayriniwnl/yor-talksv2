## Verified font repair

Windows checkout normalization made the font stylesheet and most OFL notices differ from their pinned byte hashes. The root audit restored their original LF representation and added scoped Git attributes. DM Mono is different: its **authentic pinned upstream notice uses CRLF**. It was downloaded from the manifest's exact Google Fonts commit `47d54ca1ebb14fd864695f1d39dc734f39017c33`; the downloaded SHA-256 was `2bada5ea45c3c63b7f1ea1f88ce9672c9e4f0c42b2c3b7378949084fe55a3066`, exactly the manifest value. Those authentic bytes were restored; its file has a specific `-text` exception so Git preserves them. No license text or manifest hash was invented or rewritten to fit local content.

`node --test tests/font-assets.test.mjs` actually ran after the repair: **1 passed, 0 failed, 0 skipped**. The test checks all 34 font bytes, local-only stylesheet references, six pinned notice hashes and the stylesheet cache key. It establishes delivery integrity and notice presence, not legal review of every asset.

## Changes and unresolved clearance

The creator store no longer substitutes a random Picsum image for a real listing with no product photograph. Both commerce views now say **No product photo supplied**. The Points Shop no longer substitutes a stock portrait for the signed-in user's missing avatar. Genuine uploaded imagery is preserved.

Requirement 19 is **PARTIAL**: font evidence and icon notices are present, while web brand/art, native assets and individual stock-photo provenance remain release clearance dependencies. Pending evidence must identify the actual creator/source, applicable license/version, permission for commercial distribution and modifications, required notices, and any relevant model/property permissions. Absence of evidence is not a finding that the asset is infringing.
