## Contract recheck on 2026-10-19

Read-only inspection covered backend branch `audit/backend-security-20261017` at `41024f2755723395b02a0d9184d9189e54943b86` and default branch `main` at `8c5a763893a53bad412946888a3c965deec46598`. `git ls-remote --symref origin HEAD refs/heads/main refs/heads/audit/backend-security-20261017` confirmed those remote heads and that `main` remains the default. No branch checkout, backend edit, merge or deployment was performed.

The three proposed integration contracts below remain unavailable in both inspected revisions:

- `registerSchema` and `acceptTermsSchema` accept the boolean `acceptedTerms`; both use `.strict()`. They do not accept `acceptedTermsVersion` or a document digest. `AuthService.acceptCurrentTerms` still records server `env.TERMS_VERSION`. Sending a speculative version field would fail current schema validation, so the frontend preserves the supported payload and its returned-version check.
- `routes/users.ts` exposes no `GET/PATCH /users/me/analytics-consent`. `ProductAnalyticsService.ingest` checks the account's analytics capability but has no independently stored optional permission check. The frontend keeps collectors unmounted and now offers no new analytics opt-in; it only permits removal of an existing device choice and queue.
- The grievance schema/route/service accepts no idempotency key and creates a fresh ticket for each accepted submission. The frontend does not invent one or claim a duplicate-free retry.
