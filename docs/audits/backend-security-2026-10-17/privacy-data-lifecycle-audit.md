## Account export contract

`GET /api/users/me/export` uses the authenticated subject, returns a no-store JSON attachment and streams a bounded keyset page from a read-only repeatable-read snapshot. It sets statement and idle-transaction timeouts, releases the connection on cancellation/failure, and uses reviewed SQL projections rather than `SELECT *`. Per-request page size is internally bounded to 1–500.

Exports exclude password/TOTP material, token/signature/evidence secrets, push endpoints/keys, other users' private browsing/audience/favorites, other buyers' shipping fields, expired/deleted ephemeral content, system queues and guest records that cannot safely be attributed. Media values are canonical references requiring current authorization, not downloadable access grants. The user-FK decision catalog is compared with the migrated database by integration tests; adding a user FK requires reviewing both relationship directions.

PRIV-06 (P3): completed technical queue entries now retain at most 1,000 records for seven days, reduced from 10,000 because canonical notification rows remain the delivery/retry source. Failed technical entries remain bounded to 5,000/30 days. Explicit `moderation:review` jobs retain completed and failed outcomes for operator disposition; this name currently has no production enqueue caller. The existing retention regression now passes with both minimization and the review exception enforced. Review-record retention still needs an approved operational schedule; this does not authorize a marketing or moderation worker.

To close PRIV-04, approve a per-store retention schedule with owners; prove scheduled cleanup and monitoring for expired reset/eligibility/ephemeral rows and terminal jobs; resolve legacy media ownership holds; obtain provider retention/erasure evidence; configure remote backup expiry and demonstrate that restoring a historical backup cannot return deleted accounts to service before deletion replay. These are evidence gates, not invented statutory deadlines.
