# Explicit ingress trust and local acceptance

Working-copy evidence based on `ba31c9fd443659bcacc9d2c8760086adf63ee082`
on `codex/media-lifecycle-20261006`. The operator has not selected or accepted
the actual public ingress. Neither the separate API hostname nor the Caddy to
Nginx path is claimed as the deployed topology.

Previously Express trusted one numeric hop. The Caddy to Nginx to API path
therefore grouped clients at the proxy address, while different reachable path
lengths could change how forwarded headers were interpreted. Nginx also
overwrote the external HTTPS protocol with its internal HTTP scheme.

`api-server/src/config/trusted-proxies.ts`, `config/env.ts`, and `app.ts` now
default to no proxy trust. `TRUSTED_PROXY_CIDRS` accepts only explicit literal
infrastructure IP addresses/CIDRs; numeric hop counts, aliases, hostnames,
blanket masks, and malformed masks are rejected. Untrusted direct connections
have forwarded identity/protocol/host headers stripped. Approved proxy peers
must send a single canonical client IP and `http` or `https`; ambiguous chains
are rejected rather than selecting an attacker-controlled element.

`ops/Caddyfile.example` overwrites forwarded client/protocol/host and strips
`Forwarded`. `social/nginx.conf` and `social/docker/15-trusted-edge.sh` ignore
incoming forwarded information by default. Optional `TRUSTED_EDGE_CIDRS`
identifies the approved Caddy peers as seen by Nginx. Only those peers can set
client IP/protocol; Nginx emits one canonical client IP to the API on both HTTP
and Socket.IO paths. Rendering rejects directive injection and blanket trust,
then invokes the actual Nginx configuration parser before startup.

The environment examples retain empty safe defaults. The isolated CI overlay
uses a dedicated `172.30.92.0/24` edge network and exact web peer
`172.30.92.10/32`; these synthetic addresses are not production facts. Database
and Redis remain private. Frontend gzip uses supported native Nginx directives
with `Vary: Accept-Encoding`, a 1024-byte threshold, and text/JS/CSS/JSON/SVG/font
types. It does not assume an optional Brotli module.

The Nginx access log uses a dedicated format with request method, `$uri` and
protocol. It omits query arguments, `$request`, and `$request_uri`, preventing
media `?token=` bearer credentials from entering the default access log.
Caddy access logging remains disabled in the example; enabling it requires
the same query-token exclusion on the actual public edge.

`middlewares/browser-origin.ts` centralizes the actual credentialed CORS
middleware. Refresh/socket origin checks now accept canonical exact approved
HTTP(S) origins, rejecting credentials, paths, trailing paths, and opaque
origins. Missing Origin remains supported for native clients.

`127.0.0.1:55447/yor_hardening_auth_20261007`, and Redis `7.2.8` at

```powershell
node --import tsx --test --test-concurrency=1 --test-timeout=45000 src/__tests__/ingress-hardening.integration.test.ts src/__tests__/trusted-origin.test.ts
```

**7 passed, 0 failed, 0 skipped, exit 0** (4.13 seconds). Tests use actual HTTP
and TCP proxy hops with different bound loopback peer/client addresses and the
actual Express trust middleware, production Redis rate limiter, authentication
service/controller, and Socket.IO server. They verify both supported path
shapes, separate client budgets, forwarded-header spoofing, direct API/Nginx
shorter paths, HTTPS detection, Secure/HttpOnly refresh cookies, exact CORS and
refresh origins, authenticated WebSocket upgrades and reconnect, and hostile
socket origins. Native Caddy/Nginx and public-edge behavior are not simulated
production acceptance.

`pnpm production-config:check` passes with 65 API schema keys. Ingress source
typechecked; the parallel integrated typecheck briefly reported unrelated
notification fixture/backup method errors. Final candidate results belong in
the main hardening report.

`ops/ingress/check-web-image.mjs` runs the built production web image and its
native Nginx parser/startup hook. Three approved/empty configurations must pass;
eight malformed, unrestricted, and injection configurations must fail. This
host has no Docker Engine, so this native container gate was not run locally;
CI must execute it for the exact candidate.

## Deployment and rollback gate

Before setting either trusted list, record every reachable path, actual peer
addresses/subnets, NAT/container gateway behavior, and firewalls. Trust only
dedicated approved infrastructure peers, never a whole shared network. Validate
that internet clients cannot reach a trusted peer address or bypass the public
edge. Verify at least two independent public clients, injected forwarded headers,
both intended path lengths and blocked alternatives, TLS, secure cookies,
approved/hostile origins, and authenticated Socket.IO upgrade/reconnect on the
actual domains. Run Caddy validation and Nginx image acceptance too. A CDN or
Vercel proxy needs its own inspected canonicalization/peer policy; no platform
is automatically trusted. Realtime/workers still require persistent services.

The startup include/script and Nginx configuration must deploy together. Empty
trusted lists are safe but aggregate limits at the proxy and lose external
HTTPS detection until correctly configured. Rolling back to numeric-hop trust
restores the defect; preserve explicit trust/canonicalization or restrict
traffic to an independently verified single ingress. No database migration is
needed for this repair.
